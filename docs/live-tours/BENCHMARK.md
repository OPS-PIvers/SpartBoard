## What blocked a green run or needed a workaround

No app code was changed. None of the gaps below is a one-line anchor tag: each new anchor also needs a registry entry and a route.

### Connector and guide

- **B1. `get_live_tour` drops material sample content.** It returns `materials[]` without `sample`, and `seedTourMaterials` (`components/tours/tourMaterialSeed.ts`) seeds only when `sample` is present, so a run JSON saved straight from `get_live_tour` plays Assign a quiz against an empty library. Workaround: copied the sample quiz into the run JSON by hand. Follow-up: include `sample` in `get_live_tour`, or have the runner fetch it.
- **B2. `upload_url` is unreachable from a cloud session.** `start_live_tour_picture_upload` returns `https://spartboard-dev.web.app/mcp/tour-pictures`, which the cloud container's egress proxy refuses. Workaround: posted to `https://us-central1-spartboard-dev.cloudfunctions.net/mcpServer/tour-pictures` with `NODE_USE_ENV_PROXY=1` and `NODE_EXTRA_CA_CERTS`. Follow-up: return the functions URL, or document the override.
- **B3. A `type` step with no value is refused.** The guide calls it a warning; `create_live_tour` refuses it with "type steps take a string value". `value: ""` is accepted and gives the intended warning. Follow-up: accept a missing value, or fix the guide.
- **B4. `editor.save:quiz` passes the dry run but never renders.** The quiz editor autosaves and has no Save button. Workaround: `editor.close:quiz`. Follow-up: drop `quiz` from `editor.save`'s keys.
- **B5. The guide doesn't mention staged demo content.** A staged Schedule already holds three demo rows (`config/tourDemoContent.ts`), so a new row is `event-4`. The first run used `event-3`, typed over "Reading" and still reported found. Follow-up: list demo content in the guide, or in `list_tour_anchors` for that widget.
- **B6. A surface has only one opener.** The route map knows one `opensWith` per surface, so the dry run refuses anchors reached a second way:
  - Roster editor: tagged, but only `classes.edit-roster` opens it; **New Class** opens the same editor. Workaround: fallbacks for Class Name, Add Student and Save (tour 6).
  - Guided Learning editor: `studio.*` and `gl-editor.*` need `gl-manager.preview-open-editor`; **New Set** opens the same editor. Workaround: fallback for Add media (tour 9).
  - Follow-up: allow several openers per surface.
- **B7. Studio or classic editor.** Resolved: everyone gets the Studio after New Set, and the classic editor opens only from the Studio header. Tour 9 shows the Studio.

### Runner and Autopilot

- **B8. `select` on a segmented settings field reports found without applying.** `chooseOption` (`components/tours/autopilot.ts`) looks for `[role="option"]`, which a segmented control lacks; on `settings.field:random#mode` it clicked, the drawer closed and the mode never changed. Workaround: two clicks on `random.mode` on the widget face (tour 5). Follow-up: handle radio or button groups in `chooseOption`, or have the dry run refuse `select` on them.
- **B9. The dummy board can't pick a file.** Guided Learning's **Add media** opens the file chooser, so Add step and the step text never appear. Workaround: Add media is a point-only step and the closing step describes adding steps. Follow-up: a sample image the runner can drop in, or a sample Guided Learning material. **Fixed:** `scripts/run-live-tour.mjs` answers every file chooser with `scripts/live-tour-assets/sample-image.png`, and on the dummy project uploads stay in the page. The Studio slide image is now the `studio.canvas` anchor (it opens the step fields). A local run of tour 9 with Add media, Add step, a click on the image and the step text passed every step.
- **B10. YouTube is blocked in the cloud container.** The video player never loads, so **Add at 0:00** stays disabled and every question step is missing. The tour is authored for a real board and should run there; it can't go green from a cloud session. Follow-up: rerun it on Paul's machine, or let the runner stub the player.
- **B11. The runner re-marks the previous step missing.** When a step's anchor is missing, the step before it also flips from found to missing in the summary, which points at the wrong step.
- **B12. Playwright expects Chromium build 1248; the container has 1194.** Workaround: symlinked the installed headless shell under a private `PLAYWRIGHT_BROWSERS_PATH`.

### App

- **B13. Calendar ID box has no anchor** (tour 4). Teachers paste their own ID, so the step points and waits.
- **B14. Help Center categories are data.** The dummy board has none, so tour 8 skips choosing a category. **Fixed:** on the dummy project the Help Center shows the default categories (minus Admin) with nine sample guides. A local run that opens Guides, picks **Quizzes & activities** (`help-center.guides.category:help#quizzes-activities`) and opens the first guide passed.
- **B15. Connect Google is hidden once Google is connected.** Every teacher signs in with Google, so tour 4 starts at the Calendar settings instead.

### New in run 2

- **B16. The dry run accepts any suffix on a field anchor with no `keys`.** `quiz-editor.option:quiz#A` and `quiz-editor.correct:quiz#A` passed, but `ChoiceOptionsEditor.tsx` tags letters lowercase, so steps 7-9 of tour 1 were missing until they became `#a` and `#b`. The label says only "by letter". Follow-up: list `keys` (or a pattern) for letter, row and event fields in `config/tourAnchors.ts` and refuse a suffix that doesn't match. **Fixed:** anchors whose keys the app computes now carry `keyPattern` and `keyHint` in `config/tourAnchors.ts` (quiz letters, Schedule rows and events, Quiz results and rubric positions), shown by `list_tour_anchors` as `key_pattern` and `key_hint`; the dry run refuses `quiz#A` and says keys look like `quiz#a`.
- **B17. On the dummy board, libraries load long after the player gives up.** The quiz library shows "Loading folders…" and hides its rows for about 27 s (`components/common/library/useFolderLibraryView.ts`), and the Video Activity widget is blank for about 39 s. The player marks an anchor missing after `ANCHOR_SEARCH_MS` (3 s, `components/tours/useAnchorElement.ts`), so tours 2 and 11 fail from their first click. Teachers on a real backend don't wait like this; the dummy backend does. Follow-up: make the dummy backend's listeners settle at once in `scripts/serve-verify.mjs` and the verify config, or have `scripts/run-live-tour.mjs` wait for the staged widgets to finish loading before step 2. Then rerun tours 2 and 11; tour 11 also covers B10. **Fixed:** on the dummy project (`VITE_FIREBASE_PROJECT_ID=dummy` with auth bypass, dev only) `config/firebase.ts` takes Firestore offline, so listeners answer from the local cache at once instead of retrying for about 30 s. Rerun locally: tour 2 (8 steps) and tour 11 (9 steps) both passed with every anchor found. B10 is still unconfirmed: tour 11's Add question step passed, but the headless YouTube player stayed black at 0:00.
- **B18. The dry run accepts `select` on a control that isn't a choice.** `random.mode` is a cycle button whose label lists four modes, so `select` with `groups` looked right. Autopilot clicked it once (to Shuffle), reported found, and the next steps were missing. Follow-up: have `chooseOption` (`components/tours/autopilot.ts`) report missing when no option matches, and have the dry run refuse `select` on anchors that aren't a select, radio group or tab strip. **Fixed:** `random.mode` carries `cycles: 'settings.field:random#mode'`, and the dry run refuses `select` on it and names that field. It also refuses `select` on a switch or a text, number, slider, list or image settings field (each field in `settings_fields` now has its `kind`). `performStep` returns false when no option matches, so the browser run marks the step missing (`no_option`) and a teacher run hands it back.
- **B19. The Style tab's own controls have no anchors.** Font, text color, card color and text size (`TypographySettings`, `SurfaceColorSettings`, `TextSizePresetSettings`) aren't in `list_tour_anchors`, so tour 7 changes the Text widget's tagged note color instead. Follow-up: tag the shared style controls once so every widget's Style tab is reachable. **Fixed:** each widget's Content-tier style fields are now in its `settings_fields` (`settings.field:<type>#fontFamily`, `fontColor`, `cardColor`, `textSizePreset` and the rest), and the Window tier is tagged `settings.window-background`, `settings.window-font`, `settings.window-text-size` and `settings.window-transparency`, revealed by `settings.tab-style`.
- **B20. A list-row warning on a list the tour just made.** The dry run warns that `roster-editor.first-name:roster-editor#row-1` differs per teacher, but in a new class row 1 is the student the tour just added. Minor. Follow-up: skip the warning when an earlier step opened the list empty, such as New Class. **Fixed:** New Class (`classes.new-class`, `classes.new-class-empty`) carries `opensEmpty: 'roster-editor'`, and the dry run skips the list-row warning on a `roster-editor` row after such a click.
