## 1. Goal

Give teachers a way to grade recorded audio responses: a question-major queue
(one question, every student, then the next question), per-slot grades keyed by
question **and** slot, time-anchored comments in milliseconds, a pinned-take
mechanism so a teacher can grade an earlier take than the winner, and a three-way
adjudication (excuse / blank / offline substitute) for slots where capture was
never available to the student.

## 2. Decisions to honor

**`GradeResult` already has a three-state lifecycle — build on it, don't
reinvent it.** `state: 'scored' | 'awaiting-grade' | 'not-attempted'` shipped
2026-08-28 by the M12 rubrics track (`types.ts:3209-3231`). `awaiting-grade`
means `pointsEarned` is a placeholder and the student is **omitted** from the
gradebook/Classroom push; `not-attempted` pushes a real 0
(`docs/rich-response-wayfinder.md:1769-1771`). This brief's new "excuse / blank /
substitute" outcomes must map onto this existing tri-state, not add a fourth
state to `GradeResult` (see §4 for the mapping).

**Grading is per-slot, keyed by question AND slot.** `slot` (`'primary' |
'addendum'`, already on `ResponseArtifact` per Brief 3.3/RR-02) is the key —
either nested `grading.{questionId}.{slot}` or composite
`grading["{qid}::{slot}"]` where an unsuffixed key reads as the primary slot
(`docs/rich-response-wayfinder.md:1775`). Pick composite-key encoding for
minimal migration cost against the shipped `grading?: { [questionId]:
WrittenAnswerGrade }` shape (`types.ts:3889`) — an unsuffixed `questionId` key
continues to mean "the primary/only slot," so **every existing `short`/`essay`
grade written before this brief remains valid with zero migration**.

**Manual grading is a property of the SLOT, never the question, never the
type.** A question can return a mixed result — an MC slot auto-scored, its
audio-addendum slot `awaiting-grade` — with the question's points the sum of
both (`docs/rich-response-wayfinder.md:1778, 3600-3624` [RR-10 sub-decision
10]). Do not gate the grading queue on `question.type === 'short' | 'essay'`;
gate it on "does this slot have an artifact needing a human," i.e. any slot
whose artifact `kind` is `'audio'` (or `'text'` addendum) needs manual grading
regardless of the question's own type.

**The queue is question-major by default: Q3 for everyone, then Q4 for
everyone** — a deliberate ordering answer, not a machine one, because the
criterion stays loaded across 30 responses instead of drifting
(`docs/rich-response-wayfinder.md:1777`). This is a change from the shipped
`WrittenResponseGrader.tsx`'s **student-major** default (`studentIdx` outer
loop, `questionIdx` inner — see §3). Media grading needs a **new** question-major
queue mode; do not silently flip written-response (`short`/`essay`) grading's
existing default, since that ticket only decided this for questions carrying a
recording slot — restrict question-major default to questions that have at
least one non-text-only (audio) artifact slot; leave the existing
student-major written-response flow as-is for pure `short`/`essay`.

**A teacher may grade an earlier take; the grade records which one.**
`WrittenAnswerGrade` gains `gradedTakeIndex?: number`
(`docs/rich-response-wayfinder.md:1772`). Scoring for the leaderboard/live
monitor still always reads the **highest** `takeIndex` (RR-A2 sub-decision 5,
unchanged) — pinning changes **provenance of the manual grade**, not the
computed/auto score. `gradingSnapshot` is **not needed for media** — a take is
immutable once committed (RR-A2 keeps every take, never mutates), so there is
no drift for a snapshot to protect against (`docs/rich-response-wayfinder.md:1774`,
first paragraph).

**Media annotations are time-anchored, in milliseconds, reusing
`WrittenAnswerAnnotation`.** `from`/`to` mean **milliseconds into the take**
instead of character offsets when the annotation is on an audio artifact
(`docs/rich-response-wayfinder.md:1774`, sub-decision 6). Reuse the existing
`WrittenAnswerAnnotation` type (`types.ts:3938-3948`) as-is — do not fork a new
type; the field semantics differ by which kind of artifact the grade's
`gradedTakeIndex`/slot points at, and that's fine, document it on the type.

**Three-way adjudication for `capture-unavailable` slots** (RR-07's final
resolution, `docs/rich-response-wayfinder.md:1968-2098`):

| Teacher choice     | Result                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------- |
| Excuse             | Omitted from the gradebook — same treatment as `awaiting-grade`                              |
| Blank              | `not-attempted` → a real 0                                                                   |
| Offline substitute | `scored`, with a **mandatory note** — no artifact ever exists; the note is the entire record |

The trigger is an `unresponded` reason on the answer entry equal to
`'capture-unavailable'` (Phase 2 scope — see §3 for whether it exists yet). The
default before a teacher acts is **`awaiting-grade`** — this is what makes a
silent zero structurally impossible (`docs/rich-response-wayfinder.md:2017-2029`).
**Excuse must not simply set `state: 'awaiting-grade'` and stop** — that state
also means "not yet graded," and a queue built naively would keep re-surfacing
an excused slot as needing attention forever. Add a boolean
`WrittenAnswerGrade.excused?: boolean` so the grading queue can distinguish
"excused, permanently resolved, omit from gradebook" from "genuinely still
pending a grade," while both compute to `GradeResult.state === 'awaiting-grade'`
for every downstream gradebook/export/LMS consumer (which is exactly the
behavior RR-07 sub-decision 5 wants — omitted either way). "Offline substitute"
requires `WrittenAnswerGrade.overallComment` (already exists,
`types.ts:3912`) to be **non-empty** before save — this is "the mandatory
note," enforce it client-side in the grading UI (there's no server-side
enforcement mechanism for this on the map; note that as an accepted gap, do
not attempt to add a Firestore rule for it — rules cannot express "field X
required only when Y").

**Whether "excused" survives the LMS boundary is unresolved by the map** —
Classroom can express "excused" natively; Schoology's AGS score model
apparently cannot (`docs/rich-response-wayfinder.md:1771`, "Injected into
RR-09"). This brief's push logic: treat `excused: true` exactly like
`awaiting-grade` (omit from the push) for **both** LMS integrations. Do not
attempt to special-case Schoology — that's explicitly unresolved and out of
scope.

**Number of takes never prices a grade.** Takes stay visible (playable in the
teacher's results view, with a count shown) and **unpriced** — no integrity
signal, no rubric adjustment, no `Warnings` column entry
(`docs/rich-response-wayfinder.md:1782, 3415-3429`).

**`isWrittenQuestionType` splits into two predicates.** Grading-path call
sites ask "does this **slot** need a human" (per-slot, per-response);
authoring/rendering sites keep asking "is this a constructed-response
**type**" (per-question) (`docs/rich-response-wayfinder.md:1783`). Do not
merge these — find the existing `isWrittenQuestionType`-style helper (search
`utils/` and `components/widgets/QuizWidget/` for the exact name/location) and
add a **new**, differently-named per-slot helper rather than changing its
signature.

**Provisional scores are always marked, never a bare number** — in the live
monitor, the results list, the export, and the student's published view
(`docs/rich-response-wayfinder.md:1776`, sub-decision 8). This brief owns the
teacher-facing surfaces (live monitor / results list / export); Brief 3.6 owns
the student-facing published view — coordinate on a shared visual/textual
convention (e.g. a "provisional" badge/asterisk) but each brief implements its
own surface.

## 5. Backward-compatibility constraints

- Every existing `grading[questionId]` entry (unsuffixed key = primary slot)
  continues to be read identically by every existing consumer — the composite
  key is purely additive.
- `WrittenAnswerGrade.gradedTakeIndex` and `.excused` are optional; every
  existing grade lacking them behaves exactly as before (`gradedTakeIndex`
  absent → scoring/grading UI falls back to the highest `takeIndex`, matching
  current behavior since takes don't exist pre-Phase-3 anyway).
- Do not modify `GradeResult`/`GradeState` (`types.ts:3204-3231`) — build
  strictly on top of the shipped shape.
- Do not change `WrittenResponseGrader.tsx`'s existing student-major default
  for pure `short`/`essay` questions — only questions carrying an audio-needing
  slot get the new question-major queue.
- **No `firestore.rules` change is required** for this brief — `grading` is
  already outside the student-write whitelist (`firestore.rules:3360` does not
  list it) and teacher/admin writes to it are already permitted by the
  existing unrestricted teacher branch. Composite keys inside the `grading`
  map are just different map keys; no rule inspects key names. Confirm this
  by reading the full `grading`-related rule block before assuming no change
  is needed — if the current rule caps the map's _size_ or validates key
  patterns, that would need a protected-file change; based on this session's
  reading it does not.
- If Phase 2's `unresponded`/`UnrespondedReason` fields don't exist yet, adding
  the minimal 3-value type here (§3) must not conflict with Phase 2's later,
  fuller version landing afterward — use the exact same field name
  (`unresponded`) and value set so Phase 2 can extend rather than replace it.
