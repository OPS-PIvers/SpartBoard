## 1. Goal

When a student commits a recorded take (audio only — video is deferred), the blob
uploads from the browser to a Firebase Storage transit path, and a Cloud Functions
callable immediately transcodes it to a Drive-previewable format and archives it to
the teacher's own Google Drive, then deletes the Firebase copy. Firebase Storage is
**never** the durable home — a failed archive is retried and the student sees the
question as **not yet submitted**, not silently parked for days.

## 2. Decisions to honor

**Storage is a transit buffer, Drive is the durable home** — Firebase Storage →
transcode → Drive → Firebase copy deleted
(`docs/rich-response-wayfinder.md:706-730`). Audio is free at Firebase's scale;
this reasoning does not change for audio-only scope.

**Archival fires immediately, per artifact, on upload**, using the teacher's
already-stored refresh token — no teacher presence required
(`docs/rich-response-wayfinder.md:752-758`).

**`ResponseArtifact` archival fields live in a sibling `artifactArchive` map, NOT
inside `answers[]`** — Firestore cannot address array elements by field path, and a
server write racing the student's whole-array rewrite would clobber
(`docs/rich-response-wayfinder.md:772-789`). `storagePath` and `uploadState` stay
on the artifact (student-written); `driveFileId`, `archiveStatus`, `archivedAt`,
`archiveError` move to `artifactArchive[artifactId]` (server-written).

**HARD CONSTRAINT (Paul, 2026-09-01, IMPLEMENTATION.md Phase 3 item 3):** a take
whose archive fails is **retried** and surfaced to the student as **not yet
submitted** — never parked for a week. The straggler sweep is **hours, not days**.
This supersedes the original ~7-day sweep language at
`docs/rich-response-wayfinder.md:791-805` — treat the "surfaced to teacher as
failed, ~7 days" framing there as **superseded by the 2026-09-01 owner note**; keep
only: Firebase copy dies on successful archive, un-archived media is swept
aggressively, and failure must reach the teacher out-of-band via the existing
`/mail` outbound queue (`docs/rich-response-wayfinder.md:791-805`). Re-scope the
sweep window to a small number of hours (recommend **2 hours**, configurable via a
top-level constant) rather than 7 days, and surface an in-flight/failed archive to
the **student** as an incomplete submission (their `uploadState` is still
`'pending'`/`'failed'`), not only to the teacher by email.

**Retention: end of current school year, not "district-lifecycle-bound"**
(`docs/rich-response-wayfinder.md:1470-1513`) — **out of scope for this brief**
(that annual sweep is separate scheduled work); this brief only needs to leave
`artifactArchive` and `answers[].artifacts[]` in a shape that annual sweep can
read later. Do not build the annual sweep here.

**webm does not survive to Drive — transcode is mandatory.** Video: MP4
(H.264+AAC). **Audio: MP3 or `.opus`** (`docs/rich-response-wayfinder.md:3729-3734,
3794-3797`). Never `.wav` (24× larger for no perceptual gain on speech,
`:3794-3797`). Record whatever `MediaRecorder` natively produces (feature-detect,
never hardcode a mimeType — store the chosen type as metadata,
`:3814-3816`); audio bitrate should be explicitly set to `32000` bps rather than
relying on Chrome's unpublished default (`:3879-3881`, `:4125`).

**Drive folder + filename convention:** the teacher's own Drive, at
`SpartBoard/Quiz Responses/{quiz}/`, mirroring where `QuizMetadata.driveFileId`
already lives (`docs/rich-response-wayfinder.md:807-818`). **Filename carries the
student's real name once it crosses into Drive** — e.g. `Nguyen_Ava__Q3.mp4`
pattern, generalized to audio, e.g. `Nguyen_Ava__Q3.m4a` — Firebase transit stays
pseudonymous (`{sessionId}/{studentUid}/...`), Drive does not
(`docs/rich-response-wayfinder.md:1324-1348`). Resolve the real name server-side
via the same pseudonym-resolution mechanism the teacher-side already uses
(`getPseudonymsForAssignmentV1` — verify exact export name in
`functions/src/studentIdentity.ts` or wherever it's currently defined before
wiring; if it's a teacher-facing-only callable today, this callable needs its own
server-side lookup, not a client-supplied name, since a hostile client could pass
an arbitrary name string).

**Firebase Storage path is fixed:** `.../{sessionId}/{studentUid}/...`
(`docs/rich-response-wayfinder.md:697, 587-589`). Use this exact prefix shape for
the new Storage path (see §5 for the concrete path and rule).

**`artifacts[]` is untrusted; integrity is a path-prefix check, not a Firestore
rule** — Firestore rules cannot iterate/validate array element shape
(`docs/rich-response-wayfinder.md:578-599`, confirmed again at `:625-630`). Storage
rules gate the **upload** by path prefix (mirror the activity-wall pattern at
`storage.rules:117-138`); any **reader** of `artifacts[].storagePath` (this
callable, the results view) must independently check the path prefix matches
`{sessionId}/{studentUid}` for the response being processed before trusting it.

**`takeLimit` is enforced in this callable, not in rules** — Firestore rules
cannot count array entries per `questionId` under any model
(`docs/rich-response-wayfinder.md:3430-3444`, `:894`). `takeLimit: number | null`
lives on the question's `recording` config block (Phase 3.1/3.2 scope — assume it
exists as `QuizQuestion.recording.takeLimit`); `null` = unlimited (the shipped
default, `docs/rich-response-wayfinder.md:3333-3362`). Before archiving a newly
uploaded take, count existing committed takes for that `questionId` in the
response's `answers[]` (i.e. count `answers` entries with that `questionId`, since
takes append as siblings — see §3) and reject with a clear error if the limit
would be exceeded. **Superseded takes are never deleted from Drive** — every
committed take is archived and kept (`docs/rich-response-wayfinder.md:3387-3398`).
Do not build a Drive delete path for takes.

**Size cap / contentType allowlist:** derived from the bitrate policy, not from
the activity-wall's 10 MB / `image/.*` rule
(`docs/rich-response-wayfinder.md:4188`). At 32 kbps Opus, a 300 s (5 min) audio
take is ~1.2 MB; set the Storage rule's `request.resource.size` cap generously
above realistic audio (recommend **5 MB**) and `contentType.matches('audio/.*')`.

**In-order upload queue for back-to-back takes (RR-A6, Phase 0 closure):** audio
uploads are ~1 s each on the measured floor, so the only remaining requirement is
that take _n_'s upload not race take _n+1_'s on the client
(`docs/rich-response-wayfinder.md:4191, 127`). Client-side: queue uploads
in-order (don't fire concurrent uploads for the same question/response), let each
finish (or fail) before starting the next.

## 4. Step-by-step implementation notes

**Step 0 — types.ts.** Nothing to add here. `ResponseArtifact` (with the
full `kind: 'text' | 'audio' | 'video' | 'whiteboard'` union — video/
whiteboard are unhandled peer modes, not omitted from the type),
`QuizResponseAnswer.artifacts`/`.takeIndex`/`.unresponded`, and
`QuizResponse.artifactArchive`/`ArtifactArchiveEntry`/`ArtifactArchiveStatus`
all ship with Phase 2 (2.1, 2.2) and 3.1/3.2, which are merged into
`dev-paul` before this item starts — use the shipped types exactly as
GLOSSARY.md documents them. `ArtifactArchiveStatus` is
`'syncing' | 'archived' | 'failed' | 'deleted' | 'delete-failed'` (the last
two are 4.1's, unused here but present on the type). If a type named in
GLOSSARY.md is missing, return status blocked — do not add it.

**Step 1 — functions/package.json.** Add `fluent-ffmpeg` + `ffmpeg-static` to
`dependencies`, `@types/fluent-ffmpeg` to `devDependencies`. Run
`pnpm --dir functions install`.

**Step 2 — new file `functions/src/quizMediaArchive.ts`.** An `onCall` callable,
e.g. `archiveQuizMediaArtifact`, called by the student's client right after a
successful Storage upload completes (i.e. driven by the upload path, not a
Storage-trigger, so it can return archive status synchronously to the uploader —
mirrors RR-03's "transcode is on the critical path of every upload"
(`docs/rich-response-wayfinder.md:865, 4134`)). Accepts
`{ sessionId, responseKey, questionId, artifactId }`. Steps inside:

1. `request.auth` required. Load the session doc to get `teacherUid`.
2. Load the response doc; find the artifact by id in `answers[].artifacts[]`;
   confirm `request.auth.uid === response.studentUid` is **not** required here
   (the callable acts server-side after upload, called by the student who owns
   the response — verify `request.auth.uid` matches `studentUid` on the response
   for authorization).
3. **Path-prefix check**: reject if `artifact.storagePath` doesn't start with
   `{sessionId}/{studentUid}/`.
4. **Take-limit check**: count sibling `answers[]` entries with the same
   `questionId` that already have an `artifactArchive` entry (or any
   `uploadState !== 'failed'`); compare against
   `question.recording.takeLimit` (load quiz question config — via
   `QuizSession.publicQuestions` is enough if `recording.takeLimit` is projected
   there, otherwise load via Drive/QuizData; confirm which is authoritative in
   Phase 3.1/3.2's implementation before wiring). If exceeded, throw
   `resource-exhausted` and do **not** archive.
5. Write `artifactArchive[artifactId] = { archiveStatus: 'syncing',
archiveStartedAt: Date.now() }` (merge write, outside `answers[]`).
6. Download the Storage object (mirror the size-guard pattern from
   `driveArchive.ts` — cap at 5 MB per §2, `HttpsError('invalid-argument', ...)`
   on overflow or unreadable size).
7. Transcode: pipe the downloaded buffer through `fluent-ffmpeg` (write to a
   `/tmp` file — Cloud Functions instances get ephemeral disk — `ffmpeg-static`'s
   binary path passed via `ffmpeg.setFfmpegPath(ffmpegStatic)`) to
   `aac` (M4A container, per `CONVENTIONS.md`) at a fixed bitrate (e.g. 64
   kbps output is plenty for 32 kbps-source speech; keep it simple and don't
   try to preserve source bitrate). Output filename base: resolve the
   student's real name server-side (do **not** trust a client-supplied name)
   and the question's 1-based position or id — e.g.
   `{LastName}_{FirstName}__Q{n}.m4a`; if a
   real-name resolver isn't available to this callable, resolving names is a
   **blocking prerequisite** — flag this explicitly rather than falling back to
   a pseudonym in the filename, since RR-04 sub-decision 1 requires the real
   name in Drive.
8. Call `refreshGoogleAccessTokenForUid(teacherUid)` for a fresh access token,
   then reuse `uploadBlobToDrive`-equivalent logic (import/reuse from
   `driveArchive.ts` if exported, or duplicate minimally) to create
   `SpartBoard/Quiz Responses/{quizTitle}/{filename}.m4a` and upload the
   transcoded bytes. **Do not call `makeDriveFilePublic`** — unlike Activity
   Wall photos, these are not meant to be publicly shared; RR-03 sub-decision 6
   gates playback through a callable that verifies uid + publish state (see
   Brief 3.6), not a public Drive link.
9. On success: write `artifactArchive[artifactId] = { archiveStatus:
'archived', driveFileId, archivedAt: Date.now() }` (merge, clearing
   `archiveStartedAt`/`archiveError`); delete the Storage object
   (`ignoreNotFound: true`); patch the artifact's `storagePath` to `null`/absent
   is **not** possible from a server write into `answers[]` (student-owned) —
   leave `storagePath` as-is on the student's array entry; the reader (Brief
   3.6, Brief 3.4) must prefer `artifactArchive[id].driveFileId` when present
   and treat a present `driveFileId` as "no longer live at storagePath."
10. On failure: write `artifactArchive[artifactId] = { archiveStatus: 'failed',
archiveError: message }` (merge). **Do not throw a fatal error back to the
    caller if this is being invoked from a retry sweep** — from the direct
    student-triggered call, do rethrow so the client can retry immediately.

**Step 3 — client-side, `hooks/useQuizSession.ts` / wherever the recording
capture flow lives (Phase 3.1 scope, out of this brief, but the interface this
brief needs from it):** after `MediaRecorder` stop + commit, upload the blob to
`quiz_response_media/{sessionId}/{studentUid}/{artifactId}.{ext}` via
`uploadBytesResumable` (mirror `hooks/useStorage.ts` patterns, e.g. lines
120-165), write the `ResponseArtifact` with `uploadState: 'pending'` into the
answer via `submitAnswer`, then on upload completion call
`archiveQuizMediaArtifact` and update local `uploadState` to `'uploaded'` on
success or `'failed'` on error (retry once automatically, then surface a retry
button — see Brief 3.6/3.4's dependency on "not yet submitted" framing). Queue
uploads **in order** per response (a simple promise chain keyed by
`sessionId+studentUid` is sufficient — no need for anything fancier given ~1 s
audio uploads).

**Step 4 — straggler sweep, new file `functions/src/sweepStuckQuizArchives.ts`.**
`onSchedule`, runs hourly. Query `artifactArchive` entries stuck at
`archiveStatus: 'syncing'` or `'failed'` older than **2 hours**
(`archiveStartedAt` cutoff) — this requires a collection-group query or an
index; since `artifactArchive` is a map field (not a subcollection), the sweep
must iterate `quiz_sessions/*/responses/*` documents modified recently rather
than querying the map directly (Firestore cannot query into map field values
generically) — model this on `finalizeIdleQuizAttempts.ts`'s query-then-filter
pattern (query `responses` by `lastWriteAt` or an added `hasStuckArchive:
boolean` denormalized flag set at write time in Step 2, indexed, to make the
sweep queryable — **recommend adding `hasStuckArchive?: boolean` to
`QuizResponse` as a server-maintained flag, set true at `artifactStatus:
'syncing'`/`'failed'` write, cleared on `'archived'`**, to avoid an
unindexable full collection-group scan). Retry each stuck artifact by
re-invoking Step 2's archive logic directly (as a plain async function
exported and shared between the callable and the sweep — don't call the
`onCall` HTTPS endpoint from server code). Send **one** `/mail` doc per
affected teacher (dedupe by `teacherUid` within a run) summarizing which
students/questions are stuck, mirroring `rolloutRequestEmail.ts:85-107`'s
`db.collection('mail').doc(id).set({ to, message })` shape.

```
// Quiz recorded media — student uploads once per artifact; transit buffer
// only, deleted by the archival callable after Drive archival succeeds.
match /quiz_response_media/{sessionId}/{studentUid}/{fileName} {
  allow read: if request.auth != null &&
    (isAdmin() || request.auth.uid == studentUid ||
     firestore.get(
       /databases/(default)/documents/quiz_sessions/$(sessionId)
     ).data.get('teacherUid', '') == request.auth.uid);
  allow create: if request.auth != null &&
    request.auth.uid == studentUid &&
    request.resource.size < 5 * 1024 * 1024 &&
    request.resource.contentType.matches('audio/.*') &&
    firestore.exists(
      /databases/(default)/documents/quiz_sessions/$(sessionId)
    );
  allow delete: if request.auth != null &&
    (isAdmin() ||
     firestore.get(
       /databases/(default)/documents/quiz_sessions/$(sessionId)
     ).data.get('teacherUid', '') == request.auth.uid);
}
```
