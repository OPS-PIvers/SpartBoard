# Brief 1.3 — Absent-means-unanswered, four export/aggregation sites

Source of truth: `docs/rich-response-wayfinder.md`. Map tickets: RR-06 (closed
2026-08-07, finding 4), RR-08 (closed 2026-08-06). Implementation order:
`docs/rich-response/IMPLEMENTATION.md`, Phase 1 fix 3.

This is a standalone implementation brief. You have no access to the
conversation that produced it — everything you need is below or in the two
docs cited above.

## 1. Goal

Four export/aggregation sites currently infer "the student didn't answer
this question" from **the absence of an `answers[]` entry for that
`questionId`**. Brief 2.2 (RR-08's completeness model) makes every
passed-over question write an entry — so once it ships, these four sites
stop seeing absence at all, and each one's "unanswered" cell/state silently
becomes "answered, incorrect" (`'0'`) instead. This brief teaches all four
to check the entry's new `unresponded` marker (from brief 2.2) instead of —
or in addition to — entry absence, so the distinction survives.

## 2. Decisions to honor

**RR-06 finding 4** (`docs/rich-response-wayfinder.md:1763`), the audit that
opened this ticket:

> RR-08 silently inverts the "absent means unanswered" contract in **four**
> places, for every question in every quiz — not just for media. The pattern
> is always the same: a consumer treats **a missing entry** as "not
> answered," and RR-08 makes every question write one.

The four sites, quoted verbatim from the map (current locations in §3 — the
map's own line numbers are from early August and have drifted):

- (a) `assignmentExportShared.ts:170-178` emits `''` **only when no entry
  exists** for a question. Once every question writes one, the lookup
  starts hitting, `gradeFn` runs, and the cell becomes `'0'` — which
  `quizDriveService.ts:817-821` documents as **"answered, incorrect."** The
  empty cell stops occurring at all.
- (b) `readPlcSheet` (in `quizDriveService.ts`) parses those `'0'`/`''`
  cells back out for PLC cross-teacher aggregation — inherits (a)'s
  corruption on the read side.
- (c) `plcContributions.ts:99-114` — the **Firestore-native** replacement
  for the Sheets reader, not the Sheets path — does
  `if (answer === undefined) continue`, and `types.ts:387-391` documents its
  output contract as **"Absent keys = not answered. Value `0` = answered
  incorrectly."**
- (d) `quizDriveService.ts:718-741` builds an `answeredSet` per response
  (for the PLC results-sheet "# Answered" stats column), which becomes
  **every question for every student** once RR-08 ships.

**The stated ordering rule** (RR-06 `:2504`, echoing RR-A2's identical rule
for brief 1.2): this fix "must land with this ticket's change or before it,
[never after] — same failure shape, same rule as RR-A2's four-consumer
`takeIndex` change: never after." Concretely: **this brief must ship before
or alongside brief 2.2** (the ticket that makes every question write an
entry). If 2.2 ships first, there is a live window where every "unanswered"
export cell and every PLC aggregate reads as "answered incorrectly" for
every student, on every quiz, silently.

**RR-08's vocabulary this brief consumes** (`docs/rich-response-wayfinder.md:2245-2256`,
sub-decision 2 — built by brief 2.2, not this one):

```ts
interface QuizResponseAnswer {
  status?: 'draft' | 'submitted'; // finality — unchanged
  unresponded?: UnrespondedReason; // NEW — absent means the student responded
}
```

An entry with `unresponded` set means the student did **not** provide a
response for this question (for one of several reasons — passed over,
expired, abandoned, or a capture-unavailable device). An entry with
`unresponded` absent means the student **did** respond — this is the new
test to use everywhere these four sites currently test "does an entry
exist at all."

**Do not infer from `answer === ''`.** RR-08 explicitly rejected this
(`:2263-2267`): a written-response question with a legitimately empty
`answer` (student read the essay prompt, typed nothing, and pressed Submit —
`QuizStudentApp.tsx`'s written-response Submit is deliberately ungated) is a
real, scored `'0'`, not an `unresponded` slot. And per RR-02, a pure-audio
response also legitimately stores `answer: ''` while being fully answered
(the content lives in `artifacts[]`). **The only correct signal is the
`unresponded` field itself**, never string emptiness.

## 3. Key files

Verified against the current tree 2026-09-01:

- `utils/assignmentExportShared.ts` — `buildResultsSheetData`, lines
  73-235 overall; the specific dedup/lookup logic is at **lines 167-198**
  (map cited 170-178 — close). `answerMap` is built by first-occurrence dedup
  (lines 182-188 — see brief 1.2 for the parallel `takeIndex`-ordering
  concern in this same block, a related but separate fix). The grade-and-emit
  loop is lines 194-198 and 203-210:
  ```ts
  for (const q of questions) {
    const ans = answerMap.get(q.id);
    if (!ans) continue;               // <-- absence gate; grades map has NO entry
    grades.set(q.id, gradeFn(q, ans.answer, r));
  }
  ...
  const baseCell = !grade                          // <-- absence gate again
    ? ''
    : grade.state === 'awaiting-grade'
      ? 'Ungraded'
      : formatExportPoints(grade.pointsEarned);
  ```
  Once every question writes an entry, `ans` is always truthy, `grades.set`
  always runs, and `baseCell` falls through to
  `formatExportPoints(grade.pointsEarned)` — `'0'` for an unanswered
  question, because `gradeFn` (ultimately `gradeAnswer`) has no way to know
  the entry represents non-response rather than a real blank.
- `utils/quizDriveService.ts`:
  - `readPlcSheet` (lines 827-898) is a **pure Sheets-row parser** — it does
    not itself interpret cell values as "answered"/"unanswered." It returns
    `questionAnswers: string[]` per row (line 893) and documents the cell
    contract at lines 815-821 (`'' → unanswered`, `'0' → answered
incorrect`, positive number → answered correct). **This function itself
    needs no code change** — the fix belongs at the export side (item a,
    which produces the cells this function reads back) and at any consumer
    of `questionAnswers` that still relies on the documented contract. As of
    this writing, grep finds **no in-repo consumer of
    `readPlcSheet`'s `questionAnswers`** outside `quizDriveService.ts`
    itself and its test file — `hooks/usePlcContributions.ts`'s own header
    comment (lines 1-4) calls itself "the Firestore-native replacement for
    `quizDriveService.readPlcSheet`," suggesting the Sheets-read path may be
    legacy/PLC-import-only now. **Confirm whether any live consumer reads
    `readPlcSheet().rows[].questionAnswers` before spending effort here** —
    if none exists, this map site (b) reduces to "keep the doc comment
    accurate" rather than a functional fix, since fixing (a) at the write
    side automatically fixes what this function reads back.
  - The `answeredSet` builder for the PLC results-sheet "# Answered" stats
    column is at **lines 718-751** (map cited 718-741 — accurate). Current
    shape:
    ```ts
    for (const a of firstOccurrenceAnswers.values()) {
      const q = questionMap.get(a.questionId);
      if (!q) continue;
      answeredSet.add(a.questionId); // <-- adds on ANY entry, no unresponded check
      if (gradeFn(q, a.answer, r).isCorrect) correctSet.add(a.questionId);
    }
    ```
    This is a **presence-based `answeredSet`**, structurally identical to
    the audit's finding (d). Once RR-08 ships, every entry (including
    `unresponded` ones) adds to `answeredSet`, inflating "# Answered" to the
    full question count for every response.
- `utils/plcContributions.ts` — `buildContributionDoc`, the loop is at
  **lines 91-111** (map cited 99-114 — close):
  ```ts
  for (const q of questions) {
    const answer = answerByQuestionId.get(q.id);
    if (answer === undefined) continue;   // <-- absence gate
    ...
    const grade = gradeAnswer(q, answer, manualGrade);
  ```
  `answerByQuestionId` is built at lines 91-95 by first-occurrence dedup
  over `sortedAnswers` (already sorted by `answeredAt` above this snippet —
  confirm exact line by reading the file; the dedup loop itself mirrors the
  pattern in `assignmentExportShared.ts`). Same fix shape as (a): the
  `undefined` check needs to become (or be joined by) an `unresponded`
  check, and the map needs to carry the whole answer entry (or at least the
  `unresponded` flag) rather than just the `answer` string, since the
  string alone cannot express the distinction.
- `types.ts:380-405` — `PlcContributionResponse` interface. The doc comment
  (lines 384-386, and again 400-403 on `pointsByQuestionId`) documents the
  exact contract this brief must preserve: **"Absent keys = not answered.
  Value `0` = answered incorrectly."** After this fix, `pointsByQuestionId`
  must still omit the key for an `unresponded` slot — the fix is entirely
  about correctly computing which case applies, not about changing this
  interface's documented contract.
- `types.ts:815-821` region — actually see `utils/quizDriveService.ts`
  lines 815-821 (not `types.ts`) for the Sheets cell-contract doc comment
  quoted above; confirm exact location when editing, comments drift.
- `hooks/usePlcContributions.ts` (full file, ~50-line header comment) —
  confirms `plcContributions.ts` is the live, owner-scoped read path;
  `readPlcSheet` appears legacy/import-adjacent (see note on item b above).

## 4. Step-by-step implementation notes

1. **Confirm brief 2.2's `unresponded` field exists** on
   `QuizResponseAnswer` before starting (`types.ts`, search for
   `unresponded`). If it hasn't landed yet, coordinate — this brief cannot
   be meaningfully tested without it, though the code changes can be written
   defensively (treat a hypothetical future field as optional, which it is
   by construction).
2. **`assignmentExportShared.ts`:** change the two absence checks (§3
   snippet) to also treat an `unresponded`-marked entry as "no answer for
   export purposes":
   ```ts
   const ans = answerMap.get(q.id);
   if (!ans || ans.unresponded) continue; // NEW: unresponded === no cell
   ```
   and correspondingly the `baseCell` fallthrough — `!grade` already
   produces `''`, so gating `grades.set` on `!ans.unresponded` (rather than
   just `!ans`) is sufficient; no second edit needed at the `baseCell` site
   since `grade` will simply be unset for that question, same as today's
   pure-absence case. Verify by reading the surrounding lines before
   editing — do not assume the exact variable names above are final without
   checking the current file.
3. **`quizDriveService.ts` `answeredSet` builder (lines 718-751):** add the
   same guard where entries are added to `answeredSet`:
   ```ts
   for (const a of firstOccurrenceAnswers.values()) {
     const q = questionMap.get(a.questionId);
     if (!q) continue;
     if (a.unresponded) continue; // NEW: don't count a passed-over slot as answered
     answeredSet.add(a.questionId);
     if (gradeFn(q, a.answer, r).isCorrect) correctSet.add(a.questionId);
   }
   ```
4. **`quizDriveService.ts` `readPlcSheet`:** first, grep the current tree
   for any live consumer of `.rows[].questionAnswers` beyond this file's own
   test. If genuinely none exists, leave the function's parsing logic
   unchanged (it's a faithful raw-cell reader; the fix at step 2 already
   fixes what it reads) and just verify the doc comment (lines 815-821)
   still matches reality after step 2 lands. If a live consumer is found,
   that consumer needs the same `unresponded`-aware fix as steps 2-3 — treat
   it as a fifth site and note it in your PR.
5. **`plcContributions.ts` `buildContributionDoc`:** the dedup map currently
   loses everything except the raw `answer` string. Change it to retain
   enough of the entry to check `unresponded`:
   ```ts
   const answerByQuestionId = new Map<string, QuizResponseAnswer>(); // was Map<string, string>
   for (const a of sortedAnswers) {
     if (!answerByQuestionId.has(a.questionId)) {
       answerByQuestionId.set(a.questionId, a);   // store the whole entry, not just a.answer
     }
   }
   ...
   for (const q of questions) {
     const entry = answerByQuestionId.get(q.id);
     if (!entry || entry.unresponded) continue;   // NEW
     const answer = entry.answer;
     ...
     const grade = gradeAnswer(q, answer, manualGrade);
   ```
   Check the exact type used for `sortedAnswers`/`answerByQuestionId` in the
   current file before editing — it may already be typed narrowly (e.g.
   `Pick<QuizResponseAnswer, 'questionId' | 'answer'>`), in which case widen
   the picked type to include `unresponded` rather than switching to the
   full interface.
6. **Do not touch `pointsByQuestionId`'s contract or `PlcContributionResponse`'s
   shape.** The fix is entirely inside `buildContributionDoc`'s loop body —
   the documented "absent key = not answered" contract on the _output_
   interface is exactly what this brief restores, not something it changes.
7. **Cross-check brief 1.2's overlapping files.** `assignmentExportShared.ts`
   and `quizDriveService.ts` both also appear in brief 1.2 (the
   `takeIndex`-ordering fix) for an unrelated first-occurrence-dedup
   concern. If both briefs land close together, coordinate to avoid a merge
   conflict — the two fixes touch adjacent lines in the same dedup loops but
   are logically independent (one is about _which_ entry wins per
   `questionId`, this one is about _whether_ the winning entry counts as an
   answer at all).

## 5. Backward-compatibility constraints

- `unresponded` is optional. Every existing Firestore document (all of them,
  today) has no `unresponded` field on any answer entry, so every
  `entry.unresponded` check above evaluates to `undefined` (falsy) on
  legacy documents — meaning **this brief's changes are a no-op until brief
  2.2 starts writing the field.** Verify this explicitly: run the existing
  export/PLC test suites unmodified against fixtures with no `unresponded`
  field anywhere and confirm identical output to before this change.
- No Firestore rules changes. This is a read-side computation change only —
  nothing new is written to Firestore by this brief.
- No change to the documented cell contract
  (`''`/`'0'`/positive-number) in the Sheets export or to
  `PlcContributionResponse`'s "absent key = not answered" contract — this
  brief exists specifically to **preserve** those contracts against a change
  elsewhere (brief 2.2), not to alter them.
- `readPlcSheet`'s raw parsing behavior (§4 step 4) should not change unless
  a live consumer is found that needs it — avoid speculative changes to a
  function whose only confirmed callers are its own test file.
