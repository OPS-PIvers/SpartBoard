# Live tours: a consistent start and a feedback loop for Claude

Goal: a live tour that an admin asks Claude for in claude.ai starts from the same screen for every teacher, adds widgets the same way for every teacher, and gets a second pass from Claude after the admin has played it once, without the admin rewriting steps by hand.

Scope was settled in a design interview with Paul on 2026-10-14. This document is the contract. Each PR is self-contained: an implementer should be able to build it from the PR text plus the code, without the interview. It follows on from `docs/plans/LIVE_TOUR_ONE_SHOT.md`, whose decisions (D1 to D18) still hold.

**Code references** were taken at `dev-paul` commit `566821e`. Symbol names are authoritative and line numbers are hints; if a line number is off, grep for the symbol.

**Release:** no flag (Paul's call). PR 1 changes how every tour plays for teachers; Paul treats that as making tours play the way they were meant to. PRs 2 and 3 are admin-only tooling. Add one teacher-facing `public/changelog.json` note at the `main` release that includes PR 1, for example: "Tours start from the same screen every time, so the steps always match what you see."

Out of scope: a server-side headless browser run for claude.ai (revisit once the playtest loop has been used), browser fullscreen at tour start, changes to tour chrome styling (`TOUR_LIGHT_CHROME.md`).

## Why

- **The frame a tour starts on differs per teacher.** `Dock` keeps `isExpanded` in local state (`components/layout/Dock.tsx:356`) and the runner opens it only when a step's anchor needs it (`'dock-expanded'` in `SATISFIERS`, `components/tours/tourPrerequisites.ts`). A teacher who left the Dock open, the sidebar menu open, the widget library open or annotation on starts the tour on a different screen from the one the author saw. The step pictures and wording then don't match.
- **`dock.item:<type>` assumes the widget is in that teacher's Dock.** `dockItems` comes from `useToolVisibility()`. Teachers hide widgets, file them in folders and reorder them, so "click the Timer in the Dock" works for one teacher and fails for another. The dry run (`functions/src/mcp/tourDryRun.ts`) cannot know.
- **The Dock can sit on the left or right** (`dockPosition`, read in `Dock.tsx` and `DashboardView.tsx`). Auto-stage (`components/tours/tourAutoStage.ts`) and wording like "at the bottom" assume one place.
- **The collapsed Dock shows per-board quick-access buttons** (`quickAccessWidgets`), so even the collapsed frame looks different between boards.
- **A tour offered to a teacher can rely on a widget that teacher can't use.** `isTourRunnable` (`components/tours/publishedTours.ts`) checks only that a published snapshot exists.
- **Claude in claude.ai never sees the tour play.** There is no browser run there (guide, "The browser run"). The editor already uploads step pictures when an admin plays a draft (`useEditorThumbnails`) and tracks missing steps (`tourEditStore` `missing`), and teacher runs record misses (`components/tours/tourRuns.ts`), but `get_live_tour` returns none of it. The admin's only way to say "this step is wrong" is to fix it by hand.
- **Rules the guide states are not checked.** Opening and closing `board.whole` steps, the voice rules and staging hygiene are only in prose, so Claude can drift from them without a warning.

| C8  | Bookends                  | The first step observes `board.whole`, and the last step is an `observe`. A save that breaks this is an error on `create_live_tour`. On `update_live_tour` with `steps` it is an error only if the stored tour already met the rule, so recorded drafts that never had bookends can still be edited; otherwise it is a warning. `step_text` updates are never checked for it.                                                                                                                                                                                                                                                                                 |
| C9  | Playtest loop             | When an admin plays a tour in the editor, the editor records a playtest on the set: when, who, the published state it ran against, and each step's result (`found`, `missing`, `left` for a step left to the teacher, `not-reached`). It writes on reaching the last step or on leaving the editor play. The step pictures already upload as thumbnails. `get_live_tour` returns `last_playtest`, with `stale: true` when the steps changed after it. Small consequences, not separate decisions:

- The Open Tools insert uses the English label from `locales/en.json` (`sidebar.header.openTools`, "Open Tools"). If that label changes, `tests/liveTourGuideSync.test.ts` (or a new test beside the insert) must fail.
- The clean start runs before staging and before the welcome card, so the first step picture in the editor, the browser run and a teacher's run all show the same frame.
- Restoring the frame on teardown restores only what the clean start changed. A drawer or menu the teacher opens during the tour stays as they left it, matching the "teacher's own toggle wins" rule in `SATISFIERS`.
- Self-heal (`tourSelfHeal.ts`) can rely on C1: replaying a route always starts from the same frame.

## Data model

All new fields are editor/connector-only and never reach the published snapshot.

```ts
// types.ts, on GuidedLearningSet
tourReviewNote?: { text: string; by: string; at: number };
tourPlaytest?: {
  at: number;
  by: string;            // admin email
  fingerprint: string;   // fingerprint() of the set it ran, for `stale`
  steps: { stepId: string; result: 'found' | 'missing' | 'left' | 'not-reached' }[];
};

// types.ts, on GuidedLearningStep
reviewNote?: { text: string; by: string; at: number };
```

- Add `tourReviewNote` and `tourPlaytest` to `NOT_PUBLISHED` in `components/tours/tourSnapshot.ts` and its mirror in `functions/src/glTours.ts`.
- `buildTourContent` strips `reviewNote` from every step; mirror it server-side.
- Notes cap at 1,000 characters. `firestore.rules`: no change if the set doc's existing write rule covers editor writes (check `building_guided_learning` rules); otherwise allow the two keys for admins only, using the shorthands.

## PRs

All target `dev-paul`, in order. Each lists its tests; run `pnpm exec vitest related --run <files>` locally, CI does the rest. Every new control gets a `tourAttr` anchor registered in `config/tourAnchors.ts` and placed on a surface in `config/tourSurfaces/`.

### PR 1: Clean start (C1 to C5)

- `components/tours/tourFrame.ts` (new): a small external store (same pattern as `context/dashboardCanvasStore.ts`) holding the tour frame override while a tour runs: `{ active: boolean; dockPosition: 'bottom'; pinnedDockTypes: WidgetType[]; showQuickAccess: [boolean, boolean] }`, plus `useTourFrame()`. A window event `spart-tour-frame-reset` asks every frame surface to close its menus.
- `components/tours/LiveTourRunner.tsx`: on start, before staging, dispatch the reset, set the override, collapse the Dock (`TOUR_DOCK_EVENT` with `expanded: false`), close annotation (`closeAnnotation`), close any open settings drawer (`setSettingsOpen(id, false)`), set zoom to 1. Record what changed and restore it on teardown. Compute `pinnedDockTypes` from the steps' `dock.item:<type>` refs that are not visible top-level Dock items.
- `components/layout/Dock.tsx`: listen for the reset (close More, roster, remote, live info, folder menus, library, edit mode); read the effective position as `tourFrame.active ? 'bottom' : dockPosition`; render a temporary `DockItem` per `pinnedDockTypes` entry at the front of the expanded Dock with `tourAttr('dock.item')` and `data-tour-widget-type`; hide quick-access buttons per `showQuickAccess`.
- `components/layout/DashboardView.tsx`: the same effective position for its layout padding.
- `components/layout/sidebar/Sidebar.tsx`: close on the reset.
- `components/tours/tourAutoStage.ts`: drop any non-bottom Dock handling; the board fractions assume a bottom Dock.
- Access (C5): a `tourWidgetTypes(set)` helper in `components/tours/tourSession.ts` returns staged plus `dock.item`/`library.item` types. `useTourOffers`, `HelpResourceViewer` and the What's New tour offer filter out tours with a type that fails `canAccessWidget`.
- Changelog: the teacher note in "Release" above, added at the `main` release.
- Tests: `LiveTourRunner.test.tsx` (start resets each piece and teardown restores only what it changed; a teacher's mid-tour toggle survives teardown; the pinned button renders at the front with the right anchor for a hidden type and not for a visible one); `tourPrerequisites.test.ts` (`dock-expanded` still scrolls a visible item into view); `useTourOffers.test.tsx` (a tour with an inaccessible widget isn't offered; admin still sees it); `tourAutoStage.test.ts`.
- Verify in the browser with `verify-spartboard`: Dock on the right, expanded, library open, sidebar open; start a tour; screenshot step 1; end the tour; screenshot the restored frame.

### PR 2: Authoring checks (C6 to C8, C12 guide part)

- `functions/src/mcp/glLiveTour.ts`: `insertOpenDockStep(steps)` (C6) runs before the dry run on create and on update with `steps`; `inserted_steps` in both the dry-run and save results.
- `docs/live-tours/AUTHORING.md`: a "Where a tour starts" section (C1 to C4; never write "on the left" or "on the right" for the Dock), the Open Tools insert under Steps, the new checks under Checks, and the bookend rule. ### PR 3: Playtest, notes and Health (C9 to C11, C12 skill part)

- `types.ts`, `tourSnapshot.ts`, `functions/src/glTours.ts`: the data model above.
- Editor (`components/tours/editor/`): `useTourEditorSession` writes `tourPlaytest` from `tourEditStore`'s per-step status when the play reaches the last step or the admin stops it. `TourEditorPanel` adds the per-step **Note for Claude** textarea in the expanded step; `TourEditorSettings` adds the tour-level one. Both save like the step text. Register anchors `tour-editor.step-note` and `tour-editor.tour-note` and add them to the editor's surface.
- Connector (`functions/src/mcp/glLiveTour.ts`): `get_live_tour` returns `review_note`, per-step `review_note`, `last_playtest` (with `stale` from comparing the fingerprint) and `health` (C11; aggregate the runs subcollection server-side). `update_live_tour` accepts `resolved_notes`. Update both tools' descriptions.
- `docs/live-tours/AUTHORING.md`: a "Finish pass" section and a claude.ai hand-back line: "Play it once from the Guided Learning library (Type: **Live tours**, **Edit**), add a **Note for Claude** on any step that's wrong, then ask me to finish it." The finish pass: `get_live_tour`, fix every `missing` step in `last_playtest`, read pictures with `get_live_tour_step_picture` for every step whose text is rewritten, act on each note, save with `resolved_notes`, hand back what changed and any note left open with the reason.
- `OPS-PIvers/claude-skills`: `plugins/ops-staff/skills/spartboard/references/live-tours.md` gets the finish pass trigger ("finish the tour", "I played it", "I left notes") under "Finding and editing a tour", and the claude.ai section points at it. Merge it after this PR deploys to prod.
- Tests: `glLiveTour.test.ts` (notes round-trip and `resolved_notes`; `stale` playtest; Health counts only the published version and returns no uids); `tourSnapshot.test.ts` (notes and playtest stay out of `buildTourContent`); `useTourEditorSession.test.tsx` (playtest written at the end and on stop, with `not-reached` for the rest).
