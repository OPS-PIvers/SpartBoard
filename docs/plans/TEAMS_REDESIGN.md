# My Groups Redesign: A Purpose-Built Page Set Per Team Type

Source: Paul's design interview, 2026-10-07 (grill-me session, 52 questions across 13 rounds).
Status: decisions confirmed by Paul; nothing built. Builds on [MY_GROUPS.md](MY_GROUPS.md) (group types, building groups, auto-roster, goals) and supersedes parts of [shipped/PLC_HOME_V2.md](shipped/PLC_HOME_V2.md) (see "Superseded decisions").

## Problem

All four group types (`plc`, `department`, `building`, `mentoring`) render the same section list (`components/plc/sections.ts`) and land on the same generic Home. The only per-type difference is which sections default on (`getDefaultPlcFeatures`, `types.ts`). The result:

- PLCs land on a tile Home instead of their data, and the data they do have is plain div bars spread across per-assessment detail pages.
- The hero is a tile each member pins for themselves, so it feels arbitrary and the page reflows differently for everyone.
- Buildings get Meeting Mode, Notes and Assessments plumbing they have no use for, and nothing they do need: announcements, a calendar, a curated front door.
- Departments get an Assessments tab and a data-driven Meeting Mode, though they analyze no student data, and a Home with nothing to put on it.
- Mentoring is modelled as a small peer group, but it is really a district program: 1–2 facilitators, then every mentor and mentee in the district.
- Any member, viewers included, can toggle sections. Leads cannot set a layout for their team, and admins cannot set defaults for new teams.

## What each type is for

| Type       | Job                                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| PLC        | Look at common assessment data together and decide the instructional response (the four PLC questions).               |
| Department | Curriculum alignment, shared materials and meeting notes. No student data.                                            |
| Building   | One-to-many staff communication and shared building resources.                                                        |
| Mentoring  | A district program run by facilitators, with a private working space per mentor–mentee pair and required submissions. |

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T1  | **Shared modules, type presets.** One registry of page modules. Each type is a preset over it: which pages are on, their order, the landing page, the landing-page cards and the hero default rule.                                                                                                                                                                                                                                                                                                                                                                            |
| T2  | **Team layout, set by the lead and co-leads.** They control pages (on, off, order), the landing page, the landing-page cards (from a fixed catalog, no free-form grid) and the hero. Every member sees the same layout. Personal layouts (`users/{uid}/plc_layouts`) are retired. The `features` toggle rule (`isUpdatingPlcFeatures`, today any member) narrows to lead and co-lead.                                                                                                                                                                                          |
| T3  | **Admin type defaults.** Admin Settings gets a "Team type defaults" tab with one preset per type: pages, landing cards, hero default rule, meeting-note template and, for PLC, the goal-coach rubric (T21). Edits apply to teams created afterward only. Leads get "Reset to district default" in the layout editor.                                                                                                                                                                                                                                                           |
| T4  | **No generic Home.** Every type has a dedicated landing page, its front door. The hero lives only there, never on a working page such as Notes & Docs.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| T5  | **Lead-picked hero, item-level.** The lead pins a specific item: one common assessment's results, a learning target's trend, a goal, a doc or note, an update or a calendar. The hero renders that item in a large designed format. No per-member pins.                                                                                                                                                                                                                                                                                                                        |
| T6  | **Hero defaults and staleness.** Until the lead pins something, the admin's default rule for the type fills the hero ("follow latest"). A pin stays until the lead changes it; leads get a quiet nudge when newer data exists. Defaults: PLC = latest common assessment; Building = newest pinned update; Department = next meeting note until a doc is pinned; Mentoring = next required task.                                                                                                                                                                                |
| T7  | **Live meetings never take over the hero.** A slim "Meeting in progress · Join" banner sits above it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T8  | **Members, Settings and the layout editor move behind a team gear menu** in the team header. The rail holds content pages only. Members see the roster from the header avatars.                                                                                                                                                                                                                                                                                                                                                                                                |
| T9  | **Boards fold into Resources** for every type. Resources is the single place for shared boards, links, docs, pushed `plc_resources` and shared library items, filterable by kind. Admins set default categories per type; leads add their own.                                                                                                                                                                                                                                                                                                                                 |
| T10 | **What's-new drawer.** "Since you were here", your action items and activity move into a "What's new · N" / "My items · N" pair in the team header that opens a right-side drawer. They take no page space.                                                                                                                                                                                                                                                                                                                                                                    |
| T11 | **Meeting Mode is retired and folded into Notes.** A meeting is a note created from the team's meeting-note template. Recording and AI notes keep working on it as they do today (`PLC_MEETING_RECORDING`).                                                                                                                                                                                                                                                                                                                                                                    |
| T12 | **Meeting-note templates per type.** Admin default per type, editable by the lead for their team. PLC: the four PLC questions with data blocks. Department: agenda, curriculum and materials discussion, decisions, action items. Mentoring: check-in, goal progress, next steps. Building: none by default (the lead can add one).                                                                                                                                                                                                                                            |
| T13 | **Data blocks in notes are live.** They show current aggregates and link to the Data overview.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| T14 | **Structured Decision blocks.** A Decision block can link to an assessment question or a learning target. Action items keep assignee and due date and roll up into each member's "My items".                                                                                                                                                                                                                                                                                                                                                                                   |
| T15 | **Old meeting records** (`plcs/{id}/meetings`) list in Notes & Docs as read-only records using today's record view and export. No migration.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| T16 | **No per-class comparison anywhere.** Remove it from the Data overview, assessment detail and note data blocks. Teachers see their own class's results in their own quiz results, outside the team.                                                                                                                                                                                                                                                                                                                                                                            |
| T17 | **PLC pages:** Data overview (landing), Assessments (library), Notes & Docs, Resources. Learning Targets is no longer a page; targets and cutoffs are edited from "Manage targets" on the Data overview.                                                                                                                                                                                                                                                                                                                                                                       |
| T18 | **PLC Data overview.** Hero first; then item-level data, which always works without tags: score distribution, team average over time across common assessments, participation. A mastery-by-learning-target (or standard) layer appears on top when questions are tagged. Untagged PLCs never see an empty state, only a quiet prompt to the lead to tag. Then recent assessments and a small next-meeting / open-items strip. Built on `plcs/{id}/aggregates`.                                                                                                                |
| T19 | **Item-analysis hero** for a pinned assessment: percent correct per question with the dominant wrong answer called out (from `perQuestion` choice distribution), sorted to surface the 2–3 questions to reteach, with team average and participation as headline numbers.                                                                                                                                                                                                                                                                                                      |
| T20 | **Custom SVG chart kit.** Purpose-built components (distribution, item analysis, trend, mastery by target) designed together with one color system, real axes and labels, hover detail, light and dark. Not Recharts and not div bars. Use the `dataviz` skill. Reverses PLC_HOME_V2 D23.                                                                                                                                                                                                                                                                                      |
| T21 | **Goals.** A landing-page card that can be pinned as the hero, never a rail page. On by default for PLC; off for Department, Building and Mentoring (the lead can turn it on).                                                                                                                                                                                                                                                                                                                                                                                                 |
| T22 | **AI goal coach (PLC), refines and never writes.** It judges a draft goal against an admin-editable rubric with a strong default (student-focused rather than a teacher task; tied to a named assessment or measure; baseline and target; time frame; a practice the team will change). Output is a per-criterion check plus a suggested edit only for the criteria the goal misses. It sees the goal, the team's assessment and target names and team-level aggregate summaries, never student or per-class data. It refuses to start from an empty goal. Its own admin flag. |
| T23 | **Department pages:** Hub (landing), Notes & Docs, Resources. No Assessments page and no data. Shared quizzes, rubrics and question banks appear in Resources for reuse, without results. Goals off.                                                                                                                                                                                                                                                                                                                                                                           |
| T24 | **Department Hub:** hero (typically the curriculum map or current focus doc), the next meeting's note (created ahead of time from the department template so the agenda builds up), open decisions and action items, then recently updated docs and newly shared materials.                                                                                                                                                                                                                                                                                                    |
| T25 | **Building pages:** Hub (landing), Resources, Updates. No Notes and no meeting template by default; leadership-team meetings belong in their own Department-type team.                                                                                                                                                                                                                                                                                                                                                                                                         |
| T26 | **Building Hub:** hero, quick links, the latest 3–5 updates with "All updates" opening the archive, resources grouped by category, and an embedded Google Calendar.                                                                                                                                                                                                                                                                                                                                                                                                            |
| T27 | **Updates module (new).** Leads and co-leads post short updates (text, link, attachment); members read and react. A post can require acknowledgement (off by default), and the lead sees who has and hasn't acknowledged. Updates feed the weekly email digest and can be pinned as the hero. On by default for Building and Mentoring; available but off for PLC and Department.                                                                                                                                                                                              |
| T28 | **Calendar is an embedded Google Calendar** that the lead attaches. Shown as an agenda card or as a hero option. No SpartBoard-native events.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| T29 | **Mentoring is a program.** An admin creates it and names 1–2 facilitators as lead and co-lead. Facilitators add mentors and mentees (members tagged `mentor` or `mentee`, not viewers) and set the pairings in team settings. Mentors and mentees can edit their own workspace but not the program.                                                                                                                                                                                                                                                                           |
| T30 | **Mentoring pages:** Program Hub (landing), Workspace (facilitators see a "Workspaces" list), Updates, Resources. Goals off.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| T31 | **Workspace.** One per mentor–mentee pair. The rail reads "Workspace"; the page title is the two names. Holds check-in notes (mentoring template), action items and working docs. Never called "My pair".                                                                                                                                                                                                                                                                                                                                                                      |
| T32 | **Required tasks.** Facilitators post a task: title, instructions, due date, an optional template doc copied into each workspace, and who submits (mentee, mentor or both). The pair works on it in the workspace and submits it. Facilitators get a per-task tracker (submitted, late, not started) and can open submissions. Working docs reuse the existing Google Docs embed.                                                                                                                                                                                              |
| T33 | **Facilitators can see everything in every workspace.** The workspace header says so in one quiet line: "Program facilitators can view this workspace."                                                                                                                                                                                                                                                                                                                                                                                                                        |
| T34 | **Program Hub:** hero, your next required task and its due date, latest updates, program dates (embedded Google Calendar), resources. Facilitators also see a submission-status summary card.                                                                                                                                                                                                                                                                                                                                                                                  |
| T35 | **Rollout for existing teams.** Each team gets its type's new default layout. Any page it had switched off stays off. Personal home layouts and hero pins are retired. No content is touched.                                                                                                                                                                                                                                                                                                                                                                                  |

| Type       | Landing (hero) | Other rail pages                           | Off by default, lead can enable |

| PLC        | Data overview  | Assessments, Notes & Docs, Resources       | Updates                         |

Every type: team gear menu (Members, Settings, layout editor) and the What's-new drawer.

## Data model sketch (to firm up in slice 1)

- `Plc.layout` (lead/co-lead write): `pages: {id, enabled}[]` (ordered), `landing`, `cards: string[]`, `hero: {mode: 'default' | 'pinned', ref?}`. Absent reads as the type preset. Replaces per-member `plc_layouts`.
- `admin_settings/team_type_defaults` (admin write): one preset per group type plus the meeting-note template and goal-coach rubric.
- `plcs/{id}/updates`, with an `acks` subcollection for posts that require acknowledgement.
- Mentoring: member records gain `mentorRole: 'mentor' | 'mentee'`; `plcs/{id}/workspaces/{workspaceId}` (members: the pair; read: the pair plus lead/co-lead), `plcs/{id}/tasks` and `workspaces/{id}/submissions`.
- Note blocks: Decision and Data block kinds on `PlcNote`.
- Rules follow the shorthand guidance in CLAUDE.md; run `pnpm run check:rules-size` per slice.

## Slices

Each slice is its own PR into `dev-paul`. UI slices get a screenshot mockup approved by Paul before merge.

1. **Framework + PLC Data overview.** Team layout model and rules (T2), admin type defaults tab (T3), landing page and hero (T4–T7), gear menu (T8), What's-new drawer (T10), Boards → Resources (T9), SVG chart kit (T20), PLC Data overview with item-analysis hero and "Manage targets" (T16–T19), per-class removal (T16), existing-team rollout (T35).
2. **Notes templates and blocks; retire Meeting Mode.** Per-type templates (T12), live data blocks (T13), Decision blocks (T14), legacy records in Notes (T15), remove Meeting Mode entry points (T11).
3. **Department Hub** (T23, T24).
4. **Building Hub, Updates and calendar** (T25–T28).
5. **Mentoring program, workspaces and tasks** (T29–T34).
6. **AI goal coach** (T22), in parallel with any slice after 1, on its own flag. Goals card placement (T21) lands in slice 1.

## Flags and release

- New GlobalFeature `teams-redesign`: `defaultAccessLevel: 'admin'`, `defaultEnabled: true`, `missingDocPublic: false`, `stage: 'preview'`, `afterLaunch: 'retire'`. Gates every slice 1–5 surface; with it off, teachers see today's pages. Requires `my-groups` for the non-PLC types. Add it to `functions/src/featureMissingDoc.ts`.
- New GlobalFeature `plc-goal-coach`: same settings, `afterLaunch: 'keep'`, `category` = groups. Gates the coach button and its callable.
- Admins always pass admin gates, so "on for Paul" means Paul plus the other `/admins`.
- Paul opens each in Admin Settings > Access > Previews > set to Public after testing in prod. When `teams-redesign` retires, delete `plc-home-v2` and Home v1/v2, Meeting Mode and `plc_layouts` with it.
- Changelog entry when `teams-redesign` opens to everyone.
