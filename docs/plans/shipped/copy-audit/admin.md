# Copy audit: admin panel (components/admin)

## 1. Area summary

The admin panel carries the heaviest permanent copy load in the app. Nearly every settings surface opens with a helper paragraph, and nearly every toggle, slider and input carries a sentence underneath. The single worst surface is Global Settings (`GlobalPermissionsManager.tsx`), where 40 feature cards each carry a description, and about 25 of those run 3-6 sentences of release-note prose ("Fail-closed: ...", "Admin-only until this is saved and opened up." repeated 16 times). The Rollouts panel has the same problem at smaller scale. The per-widget building-defaults panels copy-paste one boilerplate sentence ("These defaults will pre-configure the X widget when a teacher in <building> adds it to their dashboard.") into 17 files, often with a second "Teachers can still override..." sentence. The patterns that keep coming back are restating the label, narrating implementation (Firestore, Cloud Functions, Firebase Auth tenant filters, Drive API, "null origin"), "You can..." instructions for obvious controls, em dashes, and "Note:"/info callouts that explain where some other setting lives.

## 2. Top offenders

1. **Global Settings feature cards**, `GlobalPermissionsManager.tsx:86-358` (rendered at :1260 list view, truncated, and :1506 grid view, in full). 40 descriptions. Most of the long ones are release notes: they list every button the feature adds, say "Fail-closed" 7 times, "Admin-only until this is saved and opened up." 16 times, and point to Firestore costs, Gemini, and other admin paths. In grid view (the only view on mobile) every card shows the full paragraph. The list view already truncates them to one line, which shows one sentence is enough.
2. **"No saved settings" amber banner**, `GlobalPermissionsManager.tsx:1235` and `:1491`. It shows on every feature card that has no Firestore doc yet, which is most of the new flagged features. Every copy says "they'll be persisted to Firestore when you click Save". It repeats down the page.
3. **Rollouts panel**, `RolloutSwitchesPanel.tsx:48-90, 159`. Seven 1-3 sentence descriptions that restate the matching Global Settings descriptions word for word, plus a 2-sentence intro.
4. **Building-defaults intro paragraph** in 17 widget config panels (list in section 4). It is the same sentence every time, it sits right under a "Configure Building X Defaults" label and building tabs that already say the same thing, and 7 of them add "Teachers can still override them per-instance from the widget's Appearance tab."
5. **Announcements editor**, `Announcements/Widget.tsx` + `Announcements/EmbedConfigEditor.tsx`. Every option and toggle has a sentence under it (dismissal/activation option descriptions, targeting paragraphs, auto-deactivate, autoplay, Drive sharing, start time, the Record tab and Live tab intros). Several use em dashes, and one says "no need to remember to turn it off."
6. **Organization view headers**, `Organization/components/primitives.tsx` `ViewHeader blurb` (9 views). Every page title has a blurb, and some leak implementation details ("Firebase auth is scoped by org", "PII-free student SSO testing", "Listed students can sign in via /join"). `DomainsView.tsx:232` also has a permanent "How this connects to Firebase." info box.
7. **Assignment Modes card**, `GlobalPermissionsManager.tsx:1044` + `ASSIGNMENT_WIDGETS` (:370-397). A 2-sentence intro plus a "Submissions: ... View only: ..." sentence pair on each of the 4 rows, next to a two-button toggle that is already labelled Submissions / View only.
8. **Placeholder panels that explain where settings live**, `GuidedLearningConfigurationPanel.tsx:19-22`, `CatalystPermissionEditor.tsx:15`, `FeatureConfigurationPanel.tsx:646, 704-707`, `FlashcardsConfigurationPanel.tsx:28`. These are whole panels of prose about some other place in the app ("please interact with the widget directly on your board as a teacher or admin").
9. **Widget Builder mode picker and step guide**, `WidgetBuilder/index.tsx:352-472`. A marketing-style subtitle ("fits your skill level and widget complexity"), a sales line on each mode card ("Perfect for...", "No code needed.", "Full control over..."), and a tip on every step.
10. **Quiz languages header**, `QuizReadAloudConfigurationPanel.tsx:224`. A 2-sentence intro about billing caps, when the cap field below already has its own hint.
