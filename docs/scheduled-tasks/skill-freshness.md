- **Fix:** Add a subsection to "How Configs Reach the Widget" documenting `utils/adminBuildingConfig.ts`'s `getAdminBuildingConfig()` as the primary/required mechanism: new widget types with admin building defaults must add a validated `case '<widget-type>':` branch there (type-checking each field the way the existing `numberLine`/`checklist`/`calendar` cases do), in addition to — not instead of — building the `ConfigurationModal`/`ConfigurationPanel` UI. Keep the `SpecialistSchedule`-style in-component `featurePermissions` read documented as a legacy/alternative pattern, but stop presenting it as the primary path, since a widget's `ConfigurationModal` saving to Firestore alone does nothing for new-instance seeding without a matching `case` in this switch.
