# Implementation Plans

Generated by the improve skill on 2026-11-14 from a student UI/UX audit of the
quiz, video activity, flashcards and student home ("My Assignments"), written
against `dev-paul` at commit `db70831b`.

Each plan is self-contained: an executor needs only the plan file and the
repo. Read the plan fully before starting, honor its STOP conditions, and
update your row when done.

All four plans were executed and reviewed on 2026-11-14 and shipped together in one PR; their plan files were deleted in that PR (git history keeps them, last present at `56d13df7`).

This folder is separate from `docs/plans/` (the repo's own feature plans) and
from `AGENT_BACKLOG.md`. These are hand-off plans from one audit; delete a
plan file in the PR that finishes it, or move the folder's leftovers into
`AGENT_BACKLOG.md` if they go stale.

## Dependency notes

- The four plans touch disjoint source files and can run in parallel, one branch and one PR each, all targeting `dev-paul`.
- The one shared area is `locales/*.json`: plan 001 adds a top-level `quizSubmit` block and plan 003 adds keys inside `flashcards`. They do not overlap, but if both PRs are open at once the second to merge may need a trivial rebase.
- Suggested order if run one at a time: 001, 002, 004, 003 (by how many students each affects).

## For the maintainer

- **No feature flags are planned.** Each plan is scoped as bug fixes, recovery buttons and wording. The one real behaviour change is the confirmation before a self-paced quiz's final submit (plan 001), treated as matching the existing confirmation on part submits. Ask for a flag if you disagree; the plan says to call this out in the PR.
- **One device check is yours** (plan 004): after it ships to the dev site, sign in as a student on a Chromebook, press Sign out, and confirm you are not signed straight back in.
- **Two decisions are parked** (plan 003 notes): whether a student who cannot record may submit a Speak Check, and whether a skipped Speak Check card should be final.

## Still open

Plans 005 to 008 were executed and reviewed on 2026-11-14 and shipped together in one PR; their plan files were deleted in that PR (last present at `e75d5f25` on the session branch history, and in the PR's commits).

Left out on purpose, each needing a decision or a larger change:

- **A true per-answer "Saved" state in the quiz.** 005 added an offline banner only; a saved indicator needs pending-write tracking in `hooks/useQuizSession.ts`.
- **Small text in the flashcards player header (10 to 12px).** The player is shared with the teacher's board; resizing needs a page-size variant.
- **Stimulus zoom controls (22px)** in the quiz, left for a pass on the stimulus viewer.
- **Guided Learning's "Results locked" screen** still has no way back (its app was out of scope).
- **Video captions and a control bar**, and a network failure while joining a video still reading "session not found".
- **Speak Check policy**: whether a student who cannot record may submit, and whether a skipped card is final.
- **Translating the video activity and the student home.** Plan 009 covered the quiz only, because the quiz is the one student surface with a per-student language setting. Translating the others changes nothing until they have a language source.

## Animation audit (2026-11-19)

Generated by the improve-animations skill from a motion audit of the teacher app, written against `dev-paul` at commit `c4edf53`. Nothing was run in a browser during the audit, so every plan carries a feel check. All five are styling tweaks: no feature flag and no changelog entry.

| Plan | Title                                                                    | Severity | Effort | Depends on | Status |
| ---- | ------------------------------------------------------------------------ | -------- | ------ | ---------- | ------ |
| 010  | Add easing tokens and give every `animate-in` entrance a strong ease-out | HIGH     | S      | none       | TODO   |
| 011  | Make the Dock expand and collapse fast, with no bounce                   | HIGH     | S      | 010        | TODO   |
| 012  | Make Dock popovers rise from their icon instead of sliding in sideways   | HIGH     | S      | none       | TODO   |

| 014  | Give shared buttons press feedback and soften the Dock's press           | HIGH     | S      | none       | TODO   |

Execution order and dependencies:

- Run 010 first. 011 uses its `ease-out-strong` utility and 013 uses its `--ease-out-strong` variable; both tell the executor to stop if 010 is not merged.
- 012 and 014 depend on nothing and can run in parallel with 010.
- 011, 012 and 014 all edit `components/layout/Dock.tsx`, at different lines. Run them one after another, or rebase the later ones.
- 010 and 013 both edit `index.css`, at different places (line 15, and lines 213 to 279).
- Suggested order one at a time: 010, 014, 012, 011, 013.

Things for the maintainer to judge by eye:

- 012 starts with a reproduce step. The sideways slide was derived from how the keyframe and the inline `transform` interact, not seen in a browser.
- 013 sets the slide offset to 2% of the board width. That is a starting value; the plan tells the executor to report rather than tune it.
- 014 changes the Dock press from 90% to 95% and makes every shared `Button` and `IconButton` press to 97%, which touches most screens.

Audit findings not planned (selected 1 to 5 of 14): sidebar panel easing, popover transform origins, toast entrance and exit, dead motion classes (random wheel curve, `animate-pulse-slow`), `transition-all` on `cqmin`-sized widget internals, width-animated progress bars, reduced-motion gaps (wheel, card flips, breathing) and the duplicated reduced-motion check, a `scale(0)` reveal in Custom Widget, and the split keyframe and reduced-motion lists.

## Findings considered and rejected

- A retired student-home layout still shipping: not true. `MyAssignmentsPage` renders only `StudentLandingV2`, with no flag choosing a layout.
- Drag-only matching and ordering: both already support tap-to-place, a keyboard sensor and up/down buttons.
- Student-home read cost on each return (about 22 listeners plus one read per assignment): plausible but unmeasured. Measure before planning.
- Dark "Quiz Submitted!" wait screen after a light self-paced quiz: real inconsistency, cosmetic, left for a later pass.

## Not audited

Whiteboard and paper answers, the review game, the stimulus viewer, guided learning, mini-apps and the `/join` code page. Nothing was tested on a real device or against a live session.
